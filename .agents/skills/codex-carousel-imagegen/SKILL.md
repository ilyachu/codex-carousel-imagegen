# Codex Carousel Imagegen Skill

Собирай профессиональную карусель так, чтобы текст жил в локальном HTML/CSS, а встроенная генерация изображений Codex использовалась только как вспомогательный визуальный слой.

## Откуда брать картинки

Текст слайдов всегда живёт в локальном HTML/CSS. Картинка нужна только как фон, метафора, текстура или hero.

- Не используй локальный skill `imagegen` из `~/.codex/skills/imagegen`.
- Не проси и не используй `OPENAI_API_KEY`.
- В Codex, если встроенная генерация изображений доступна, вызывай её.
- В Claude Code, и когда пользователь просит fal.ai или Nano Banana, генерируй скриптом этого скилла. Сначала добудь ключ по разделу «Ключ fal.ai».
- Не подключай другой image API.

## Ключ fal.ai

Перед вызовом fal проверь два места, по порядку:

1. переменная окружения `FAL_KEY`
2. файл `~/.config/fal/key`

Если ключ уже есть, не спрашивай его снова.

Если ключа нет, остановись и задай один вопрос:

`Пришли ключ fal.ai. Сохраню его локально в ~/.config/fal/key, в репозиторий он не попадёт.`

Как только пользователь прислал ключ, сразу сохрани его и продолжай карусель. Не пересказывай ключ и не жди отдельного «да, сохраняй».

```bash
umask 077
mkdir -p ~/.config/fal
printf '%s\n' "$FAL_KEY" > ~/.config/fal/key
chmod 600 ~/.config/fal/key
```

В команду подставь ключ из ответа пользователя через переменную, не через файл репозитория. После записи переменную в сессии можно оставить, файл обязателен: следующий запуск читает `~/.config/fal/key`.

Ключ не печатать обратно, не писать в скилл, промты, логи, коммиты и git. Если пользователь отказался дать ключ, собери карусель градиентами и прямо скажи, что картинки fal не сделаны.

Скрипт лежит рядом со скиллом: `scripts/fal_nano_banana.py`.
В репозитории: `.agents/skills/codex-carousel-imagegen/scripts/fal_nano_banana.py`.
После установки в Claude Code: `~/.claude/skills/codex-carousel-imagegen/scripts/fal_nano_banana.py`.
Запускай тот путь, который существует.

Один файл:

```bash
python3 .agents/skills/codex-carousel-imagegen/scripts/fal_nano_banana.py \
  --prompt "editorial abstract background, no text, no letters, no logo, no watermark" \
  --out carousel-output/assets/cover-background.png \
  --aspect-ratio 4:5
```

Пачка из `image-prompts.md`, JSON-список объектов `{prompt,out,aspect_ratio}`:

```bash
python3 .agents/skills/codex-carousel-imagegen/scripts/fal_nano_banana.py \
  --jobs carousel-output/image-jobs.json
```

Модель по умолчанию: `fal-ai/nano-banana`. Другую модель передавай флагом `--model`.
Для макета 1080x1350 ставь `--aspect-ratio 4:5`.
В промте фона запрещай текст, буквы, логотипы и водяные знаки.

## Когда использовать

- пользователь просит карусель, слайды, post carousel, Instagram carousel, Telegram carousel, LinkedIn carousel или Threads sequence
- пользователь даёт текст, тему, статью, заметки, пост или тезисы и хочет сжать их до 5-10 слайдов
- финальный результат должен экспортироваться в PNG с читаемой кириллицей

## Когда не использовать

- пользователь хочет один растровый постер, где весь текст запечён в картинку
- задачу лучше решать как статью, лендинг или документ
- нужен чужой image API кроме fal.ai Nano Banana

## Значения по умолчанию

- платформа: `telegram` и `instagram`, если не указано иное
- размер: `1080x1350`
- количество слайдов: `7`
- язык: совпадает с языком пользователя; для русскоязычного запроса используй русский
- тон: экспертный, ясный, короткий, без канцелярита

## Жёсткие правила

- Не выдумывай факты, которых нет в исходнике.
- Если исходник слабый, делай концептуальную карусель и явно помечай это как авторскую структуру.
- Русский текст держи в локальном HTML/CSS, а не внутри итоговой сгенерированной картинки.
- Картинку генерируй только для обложек, фонов, метафор, текстур, иконок и необязательных hero-визуалов.
- Не запекай в картинку финальные слайды с длинным русским текстом, плотными таблицами и точными юридическими или финансовыми схемами.
- Заголовок слайда держи коротким. Цель: `<= 8` слов.
- Основной текст держи лёгким. Цель: `1`-`3` короткие строки.
- Не используй длинные тире.

## Стартовый опрос

Почти каждый запуск начинай с короткого опроса простым языком. Не пропускай этот шаг, если пользователь заранее сам не указал все четыре вещи:

- режим генерации
- площадку и тон
- визуальный стиль фона
- типографический стиль

Задавай вопросы по-человечески, а не внутренними терминами. Не пиши длинные объяснения до вопросов.

Используй такой шаблон:

1. `Как делаем карусель:`
   - `гибридно — текст отдельно, визуалы отдельно`
   - `целиком картинками`
   - `только через кодовый рендер, без Image Gen`
2. `Для какой площадки и какой нужен тон: Telegram / Instagram / LinkedIn, спокойно / бодро / почти промо?`
3. `Какой фон и настроение хочешь: журнальный, плёночный, размытый, технологичный, минималистичный, тёмный, светлый?`
4. `Какой текстовый стиль нужен: крупный заголовок, более плотный набор, строгий editorial, мягкий friendly?`

Если пользователь уже дал часть ответов, спроси только то, чего не хватает.

Если в `carousel-output/intake.json` уже есть ответы, сначала прочитай их и не задавай вопросы повторно.

Если и после этого данных мало, используй дефолты и явно зафиксируй допущения в `brief.md`.

После того как пользователь ответил на вопросы, не уходи в обсуждение плана, не пересказывай длинно бриф и не жди дополнительного подтверждения. Сразу переходи к выполнению workflow: запиши артефакты, при необходимости сгенерируй визуалы активным бэкендом, собери `carousel-data.json` и запускай export.

Если пользователь выбрал `imagegen-only`, не тащи его в React renderer без необходимости. В этом режиме:

- собери slide-by-slide prompts
- сгенерируй каждый слайд отдельной картинкой: в Codex встроенной генерацией, в Claude Code через fal.ai
- всё равно сохрани `brief.md`, `slides.md`, `style-lock.md`, `image-prompts.md`
- экспорт в `carousel-output/png/` делай напрямую из этих картинок
- явно предупреди, что длинный русский текст в таком режиме менее предсказуем

## Обязательные артефакты

Создай или обнови файлы в `carousel-skill-lab/carousel-output/`:

- `brief.md`
- `slides.md`
- `style-lock.md`
- `image-prompts.md`
- `carousel-data.json`
- `README.md`

Сохраняй визуальные ассеты в:

- `carousel-output/assets/`

Сохраняй PNG в:

- `carousel-output/png/`

Сохраняй preview build в:

- `carousel-output/render/`

## Workflow

1. Прочитай исходный материал и определи:
   - главный тезис
   - аудиторию
   - платформу
   - язык
   - желаемое количество слайдов
   - фактические ограничения
2. Запиши `brief.md`:
   - задача
   - краткое резюме исходника
   - аудитория
   - тон
   - ограничения по фактам
   - формат выхода
   - все сделанные допущения
3. Собери структуру карусели в `slides.md` как таблицу со столбцами:
   - `slide_number`
   - `role`
   - `headline`
   - `short_text`
   - `visual_idea`
   - `needs_imagegen`
   - `imagegen_prompt`
4. Запиши `style-lock.md` на языке пользователя.
   Для русского запроса пиши `style-lock.md` полностью по-русски:
   - палитра
   - типографика
   - сетка и поля
   - логика фона
   - декоративный язык
   - стиль иллюстраций
   - правила композиции
   - правила повторяемости между слайдами
5. Если визуалы действительно нужны, сначала запиши `image-prompts.md`.
6. Если режим `hybrid`, генерируй картинку только когда слайду нужен фон, метафора или иллюстрация. Промт воспроизводимый. Для фона запрети текст внутри изображения. Бэкенд бери из раздела «Откуда брать картинки».
7. Если режим `imagegen-only`, пиши отдельный prompt на каждый слайд и явно указывай композицию, объём текста, приоритет читаемости и допуск к кириллице.
8. Сохраняй результаты в `carousel-output/assets/` или сразу в `carousel-output/png/`. Не оставляй их только во временной папке генератора.
9. Если режим не `imagegen-only`, обнови `carousel-data.json`, чтобы локальный renderer мог собрать финальные слайды.
10. Если режим `hybrid` или `render-only`, запусти локальный экспорт из `carousel-skill-lab/`:

```bash
npm run export
```

11. Проверь:
   - все PNG существуют
   - текст не обрезан
   - поля читаемые
   - контраст достаточный
   - кириллица выглядит нормально
12. В финале сообщи, что сохранено и какие ограничения остались.

## Поведение после брифа

- Не останавливайся на стадии обсуждения.
- Не спрашивай "продолжать ли дальше", если пользователь уже вызвал skill и ответил на уточняющие вопросы.
- После префлайта сразу переходи к созданию файлов и сборке результата.
- Если визуалы нужны и ещё не сгенерированы, сначала запиши `image-prompts.md`, затем вызови активный бэкенд из раздела «Откуда брать картинки».
- Не выбирай визуальный стиль полностью за пользователя, если он ещё не обозначил направление. Сначала запроси режим генерации и визуальные предпочтения.
- Не молча выбирай `render-only`, `hybrid` или `imagegen-only`. Если режим не указан пользователем, спроси его явно.
- Не молча выбирай фон, настроение, размер шрифта и плотность набора. Если пользователь это не указал, спроси.

## Формат `image-prompts.md`

Для каждого ассета используй такой формат:

```text
Asset 01: cover-background
Purpose: cover illustration
Target file: carousel-output/assets/cover-background.png
Size: portrait, suitable for 1080x1350 layout support
Prompt: Editorial abstract background about [topic]. No text, no letters, no logo, no watermark. Leave negative space for headline. Palette: [palette]. Style: [style]. Composition: [composition]. Match the style lock and stay readable behind overlaid Russian typography.
```

## Контракт `carousel-data.json`

Поддерживай JSON-объект с полями:

- `meta`
- `styleLock`
- `slides`

У каждого слайда должны быть как минимум:

- `id`
- `role`
- `layout`
- `headline`
- `body`
- `visualIdea`
- `needsImagegen`
- `imagePromptKey`

Если локальный ассет уже есть, добавляй:

- `runtimeAsset`

Используй только имя файла, например:

```json
{
  "runtimeAsset": "cover-background.png"
}
```

## Контракт рендера

- Итоговый текст остаётся в React или HTML.
- Минимальный безопасный отступ от края: `72px`.
- Размер по умолчанию: `1080x1350`.
- Layout должен быть предсказуемым и в preview, и в export.
- Сильная иерархия важнее длинных абзацев.

## Если export не работает

- Если не хватает зависимостей: `npm install`
- Если не хватает Chromium: `npx playwright install chromium`
- Если фоновые картинки ещё не сделаны: продолжай с локальными градиентами и shape-based fallback, а промты сохрани на потом

## Формат финального отчёта

В конце сообщи:

- какие файлы созданы или обновлены
- где лежат финальные PNG
- ушли ли в слайды реальные картинки или только план и градиенты, и каким бэкендом они сделаны
- какой командой заново запускать export
